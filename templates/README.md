# Layer templates

Each JSON template names actions and proposed **L1 reference positions**. A profile supplies one computer's OS, installed apps, and shortcut overrides. `scripts/resolve_template.py` resolves **one layer at a time** and prints a text cheat sheet. It does not write Bazecor JSON or claim that the shortcuts work on a connected keyboard.

```sh
python3 scripts/resolve_template.py templates/vscode.json --os macos
python3 scripts/resolve_template.py templates/vscode.json --profile profiles/macbook-pro-m5.local.json --source-json examples/VirtualDefy.json
python3 scripts/resolve_template.py templates/app-launcher.json --profile profiles/macbook-pro-m5.local.json --source-json examples/VirtualDefy.json
python3 scripts/resolve_template.py templates/omarchy.json --profile profiles/omarchy.example.json
python3 scripts/resolve_template.py templates/herdr.json --profile profiles/macbook-pro-m5.local.json --source-json examples/VirtualDefy.json
python3 scripts/resolve_template.py templates/tmux.json --profile profiles/omarchy.example.json --source-json examples/VirtualDefy.json
python3 scripts/resolve_template.py templates/blender-view.json --os macos --source-json examples/VirtualDefy.json
```

The VS Code template gives explicit Mac, Windows, and Linux shortcuts for the same named actions. It deliberately does not perform a global `Cmd` ↔ `Ctrl` replacement: navigation and other defaults differ by OS. A profile may override a shortcut by `template-id.action-id`. An action without an OS shortcut or profile override is omitted and reported, not guessed. `requires_app` and `requires_environment` filter actions for a particular machine. An `available_apps` list is an assertion supplied by the user; it is not an automatic inventory. A missing profile app is reported as skipped.

`profiles/*.local.json` and `PERSONALIZATION.md` are ignored by Git because they describe one user's computers. The tracked `*.example.json` profiles show the structure. The Mac profile here records the 13 application hotkeys visible in the supplied Raycast screenshot. Its Hyper modifier expands to Ctrl+Alt+Cmd+Shift based on this Mac's Raycast setting, but test the resulting shortcut in Raycast before encoding it in Bazecor.

The Markdown output can be saved as a cheat sheet when a design is ready: `python3 scripts/resolve_template.py templates/vscode.json --os macos --source-json examples/VirtualDefy.json > vscode-macos-cheatsheet.md`. The `--format json` output preserves action IDs and resolved physical positions for a future Bazecor compiler. Neither output changes a keyboard.

Keep **L1 labels in conversation**, because “the L1 `F` position on the Blender layer” is easy to say. Store `position_id` as the durable location in a Defy template, for example `defy:left:r3:c5` (one-based physical row and column, viewed from that half). `position_l1` is a human mnemonic/hint. The resolver reads `device.keyboard` from the chosen source to turn `position_id` into its current keymap index and reports when the L1 label there has changed. Key indices are derived output, not identity. Check geometry compatibility when using another model or a substantially different Defy export. Older templates without `position_id` still use a unique L1 label and reject ambiguity.

Colors are semantic category names, with RGB(W) slots chosen only after inspecting the target palette. Suggested meanings: `navigation` blue, `search` cyan, `transform` amber, `mesh` teal, `create` green, `view` blue-violet, `workspace` purple, `session` violet, `mode` purple, and `destructive` red. These are proposed meanings, not allocated palette slots. Use the same category meaning across layers where possible; distinguish `destructive` from `create` at a glance. `activation` is a proposal; its thumb position remains open until a user selects it.

Template schema v1 keeps portable intent: `id`, `name`, `platforms`, optional `environment` and `source`, `activation`, and `bindings`. A binding has stable `id`, human `name`, `position_id`, `position_l1`, `color_category`, optional `requires_app`, and optional `shortcuts` keyed by OS. A shortcut is one chord (`Ctrl+B`) or an ordered array (`["Ctrl+B", "V"]`) with a release between steps. Prefix-driven Herdr/tmux actions use arrays; a future Bazecor encoder will have to verify and encode them as macros or another suitable feature. Profiles carry `os`, optional `environment` and `version`, `available_apps`, `hyper_modifiers`, and `shortcut_overrides`. `Hyper` expands to the profile's actual modifiers; if unset, resolution fails for that action. Keep action IDs stable so future cheat sheets and migration tools can refer to them.

The Herdr and tmux templates deliberately use the same **physical positions** for comparable tasks: H/J/K/L move among panes; V and D split; C creates a tab/window; N/P switch; Z zooms; X closes a pane; Q detaches. Their emitted keys differ, and tmux's default split bindings assume a US-style `Shift+5` (`%`) and `Shift+Quote` (`"`). Check terminal key transmission and any custom prefix before applying. A held Layer Shift is proposed because pane navigation may be repeated; One Shot Layer can be evaluated later. Herdr also documents user-defined direct `Ctrl+Alt` bindings; if chosen on a particular host, a profile override could use one chord per action and avoid keyboard macros. Confirm that the terminal and OS pass those chords through. [Herdr keyboard guide](https://herdr.dev/docs/keyboard/), [tmux Getting Started](https://github.com/tmux/tmux/wiki/Getting-Started).

The two Blender templates are a starting design based on the documented **Blender default keymap**: modeling uses familiar G/R/S transforms and nearby mesh operations, while viewport navigation gives the Defy direct Numpad view actions. Blender also ships an [Industry Compatible keymap](https://docs.blender.org/manual/en/latest/interface/keymap/industry_compatible.html); its different commands require a separate template if selected. The modeling template is context-sensitive in Blender's 3D Viewport and Edit Mode. Many of its single-letter commands already work on L1; use it as an annotated candidate and keep only actions that earn a dedicated layer position in actual use. The view template adds more distinct value on a compact keyboard: it requires actual Numpad keycodes, not number-row keys. A held Layer Shift is proposed for repeated view/orbit actions. [Blender keymap guide](https://docs.blender.org/manual/en/latest/interface/keymap/index.html), [viewport navigation](https://docs.blender.org/manual/en/3.5/editors/3dview/navigate/navigation.html).

The [VS Code default keybindings](https://code.visualstudio.com/docs/reference/default-keybindings) and [Omarchy hotkeys manual](https://github.com/omacom/omarchy/blob/quattro/manual/07-hotkeys.md) were read on 2026-10-03. The Omarchy sample is based on the current `quattro` manual while [v4.0.4 was the latest release](https://github.com/omacom/omarchy/releases) at that time; compare it with `Super+K` and your installed Omarchy version before applying it. Its source may evolve. App launch shortcuts also depend on the host app and user settings.
